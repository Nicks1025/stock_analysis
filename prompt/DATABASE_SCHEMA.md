# StockSense AI — Database Schema (Supabase / PostgreSQL)

## Overview
All tables use PostgreSQL via Supabase. Conventions:
- Primary keys: `UUID` generated by `gen_random_uuid()`
- Timestamps: `created_at TIMESTAMPTZ DEFAULT now()`, `updated_at TIMESTAMPTZ DEFAULT now()`
- All monetary values in `NUMERIC(18,4)` (supports Indian Crores with precision)
- Apply `updated_at` trigger on all tables with `updated_at` column using Supabase built-in `moddatetime` extension

---

## Extensions Required
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pg_trgm";     -- For fast ILIKE full-text search
CREATE EXTENSION IF NOT EXISTS "moddatetime"; -- For auto-updating updated_at
```

## Table 1: `users`
Stores all registered users.

```sql
CREATE TABLE users (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name              VARCHAR(255) NOT NULL,
  email             VARCHAR(255) UNIQUE NOT NULL,
  password_hash     TEXT,                         -- NULL if Google OAuth only
  phone             VARCHAR(20),
  country_code      VARCHAR(10),
  pan_number        VARCHAR(10),                  -- Optional, for tax reporting
  avatar_url        TEXT,
  role              VARCHAR(50) NOT NULL DEFAULT 'user',   -- 'user' | 'admin'
  is_email_verified BOOLEAN NOT NULL DEFAULT FALSE,
  is_phone_verified BOOLEAN NOT NULL DEFAULT FALSE,
  google_id         VARCHAR(255) UNIQUE,          -- From Google OAuth
  is_active         BOOLEAN NOT NULL DEFAULT TRUE,
  last_login_at     TIMESTAMPTZ,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_google_id ON users(google_id);

CREATE TRIGGER handle_updated_at BEFORE UPDATE ON users
  FOR EACH ROW EXECUTE PROCEDURE moddatetime(updated_at);
```

## Table 5: `stocks`
Master registry of all stocks.

```sql
CREATE TABLE stocks (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  symbol            VARCHAR(20) UNIQUE NOT NULL,   -- 'RELIANCE', 'TCS'
  yahoo_symbol      VARCHAR(30),                   -- 'RELIANCE.NS'
  company_name      VARCHAR(255) NOT NULL,
  sector_id         UUID REFERENCES sectors(id) ON DELETE SET NULL,
  industry          VARCHAR(255),
  isin              VARCHAR(20) UNIQUE,
  exchange          VARCHAR(20) NOT NULL DEFAULT 'NSE',  -- 'NSE' | 'BSE'
  market_cap_cr     NUMERIC(18,4),
  listing_date      DATE,
  face_value        NUMERIC(10,4),
  lot_size          INTEGER DEFAULT 1,
  stock_type        VARCHAR(50)[],    -- ['growth', 'dividend', 'value', 'commodity']
  description       TEXT,
  website           VARCHAR(500),
  logo_url          TEXT,
  is_index_stock    BOOLEAN DEFAULT FALSE,
  indices           VARCHAR(50)[],   -- ['NIFTY50', 'SENSEX', 'NIFTY_BANK']
  is_active         BOOLEAN NOT NULL DEFAULT TRUE,
  last_synced_at TIMESTAMPTZ,
  data_source VARCHAR(100),
  sync_status VARCHAR(50),
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_stocks_symbol ON stocks(symbol);
CREATE INDEX idx_stocks_sector ON stocks(sector_id);
CREATE INDEX idx_stocks_search ON stocks USING gin(
  to_tsvector('english', symbol || ' ' || company_name)
);
-- Trigram index for ILIKE search
CREATE INDEX idx_stocks_symbol_trgm ON stocks USING gin(symbol gin_trgm_ops);
CREATE INDEX idx_stocks_name_trgm ON stocks USING gin(company_name gin_trgm_ops);

CREATE TRIGGER handle_updated_at BEFORE UPDATE ON stocks
  FOR EACH ROW EXECUTE PROCEDURE moddatetime(updated_at);
```

## Row Level Security (RLS) — Supabase

Enable RLS on all user-data tables and add these policies:

```sql
-- users: read/update own row only
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
CREATE POLICY users_self ON users
  USING (id = auth.uid())
  WITH CHECK (id = auth.uid());

-- portfolios: only owner
ALTER TABLE portfolios ENABLE ROW LEVEL SECURITY;
CREATE POLICY portfolios_owner ON portfolios
  USING (user_id = auth.uid());

-- Repeat similar policies for:
-- portfolio_holdings, portfolio_transactions,
-- watchlists, watchlist_items, price_alerts,
-- mf_investments, refresh_tokens, otp_codes

-- Public read on: stocks, sectors, news, mutual_funds, ipo_listings, tenders
-- (no RLS needed or open SELECT policy)
```

> Note: Since backend uses `supabase-js` with the Service Role Key, RLS is bypassed in API calls. RLS is an extra safety net if direct DB access is ever used.

## Data Normalization Notes

- **3NF applied throughout:** No transitive dependencies. Sector data is not duplicated in `stocks` — only `sector_id` FK.
- **Computed columns avoided:** `invested_value` in `portfolio_holdings` is stored (denormalized) intentionally for query performance, but always recalculated on write via backend service.
- **JSONB used sparingly:** Only for `audit_logs.old_data/new_data` where schema is dynamic.
- **Arrays used for:** `stock_type[]` on stocks (a stock can be both value + dividend), `indices[]` (a stock can be in NIFTY50 AND SENSEX), `risk_factors[]` and `catalysts[]` in AI analysis.
